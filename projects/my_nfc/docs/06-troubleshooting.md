# 6. Решение проблем

## Прошивка

| Симптом | Причина / решение |
|---|---|
| Порт не появляется в системе | кабель только для зарядки — возьмите другой; установите драйвер CH343/CH9102 (или CP210x) |
| `Failed to connect to ESP32: Timed out waiting for packet header` | автосброс не сработал: запустите загрузку снова и зажмите **BOOT** во время `Connecting...`; понизьте Upload Speed до 115200; закройте монитор порта (он может занимать COM-порт) |
| `fatal error: config.h: No such file` / `Нет файла config.h` | скопируйте `config.example.h` в `config.h` |
| `Adafruit_PN532.h: No such file` | установите библиотеку Adafruit PN532 (+ Adafruit BusIO) |
| В мониторе порта «кракозябры» | скорость монитора должна быть 115200 |

## Wi-Fi

| Симптом | Причина / решение |
|---|---|
| Бесконечные точки при подключении | сеть 5 ГГц (нужна 2.4 ГГц); опечатка в SSID/пароле; слишком далеко от роутера |
| Подключается, но потом отваливается | слабый сигнал (RSSI хуже −80 dBm); прошивка переподключится сама |

## NFC / PN532

| Симптом | Причина / решение |
|---|---|
| `PN532 not found` сразу после заливки прошивки, хотя до этого работал | модуль «застрял» на шине I2C: ESP32 перезагрузилась посреди обмена, а PN532 остался с питанием. С прошивки 1.1.2 шина освобождается автоматически при старте. Если не помогло — выньте USB на 5 с (полный сброс питания) |
| `PN532 not found` | DIP-переключатели не в I2C (1=ON, 2=OFF) или переключены без перезапуска питания; перепутаны SDA/SCL; плохой контакт Dupont |
| Ту же карту повторно не отправляет, пока не поднесёшь другую | прошивки до 1.1.0 включительно ждали 3 с без карты — обновите до 1.1.2+. Сейчас карту нужно убрать хотя бы на 1 с (`SAME_CARD_COOLDOWN_MS`) |
| После обновления на 1.1.1 карты не читаются, после EN модуль не находится | баг версии 1.1.1 (вызов `setPassiveActivationRetries`, который в библиотеке по I2C оставляет ответ модуля непрочитанным). Обновите до 1.1.2+ и один раз выньте USB на 5 с |
| Модуль найден, но карты не читаются / читаются через раз | плохой контакт Dupont (пошевелите провода); карта дальше ~3 см от антенны или лежит на металле; устаревшая библиотека Adafruit PN532 — обновите её через менеджер библиотек (старые версии требовали провод IRQ) |
| Перезагрузка при поднесении карты, `Brownout detector was triggered` | не хватает питания: другой USB-порт/кабель, внешний 5V 1A на VIN |
| Не читается телефон / банковская карта | телефоны рандомизируют UID, банковские карты — ISO14443-4, UID может меняться; для учёта используйте обычные карты/брелоки |
| Не читается карта 125 кГц (EM-Marine) | это другой стандарт, PN532 работает только на 13.56 МГц |

## Вебхук

| Симптом в логе ESP32 | Причина / решение |
|---|---|
| `connection refused` | сервер не запущен; в `WEBHOOK_URL` указан `localhost`; неверный порт |
| `read Timeout` / `connection lost` | брандмауэр блокирует порт (см. [02-webhook-server.md](02-webhook-server.md#25-сеть-и-безопасность)); ПК и ESP32 в разных сетях (гостевой Wi-Fi, изоляция клиентов на роутере) |
| `[HTTP] 401` | `WEBHOOK_API_KEY` в `config.h` не совпадает с `API_KEY` в `server/.env` |
| `[HTTP] 422` | некорректный JSON / UID — проверьте, что прошивка не изменялась |
| `[HTTP] 404` | неверный путь в `WEBHOOK_URL` (должен заканчиваться на `/webhook/nfc`) |
| HTTPS не работает | проверьте `WEBHOOK_CA_CERT`; для теста закомментируйте его (будет `setInsecure`) |

## Сервер

| Симптом | Решение |
|---|---|
| Контейнер `unhealthy` / перезапускается | `docker compose logs nfc-webhook` |
| На мониторе «Переподключение…», сканы не появляются сами | сервер остановлен или прокси буферизует поток. За Nginx нужны `proxy_buffering off;` для `/api/events` |
| Порт 8090 занят | смените `HOST_PORT` в `.env` и порт в `WEBHOOK_URL` |
| Изменения `.env` не применились | `docker compose up -d` (пересоздаёт контейнер) |
| Пересылка в n8n не работает | смотрите `forward failed` / `forward returned` в логах; из контейнера `localhost` — это сам контейнер, используйте `host.docker.internal` |
