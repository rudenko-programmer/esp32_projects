# 3. Прошивка ESP32

Код: [firmware/nfc_reader/](../firmware/nfc_reader/)

| Файл | Назначение |
|---|---|
| `nfc_reader.ino` | основной скетч |
| `config.example.h` | шаблон настроек (в репозитории) |
| `config.h` | ваши настройки и пароли (в `.gitignore`, создаёте сами) |

## 3.1 Настройка

1. Скопируйте `config.example.h` → `config.h` в той же папке.
2. Заполните:

| Параметр | Что указать |
|---|---|
| `WIFI_SSID`, `WIFI_PASSWORD` | ваша сеть **2.4 ГГц** (ESP32 не поддерживает 5 ГГц) |
| `WEBHOOK_URL` | адрес приёмника, например `http://192.168.1.100:8090/webhook/nfc` |
| `WEBHOOK_API_KEY` | тот же ключ, что `API_KEY` в `server/.env` |
| `DEVICE_ID` | имя устройства, если считывателей несколько |
| `WEBHOOK_CA_CERT` | (необязательно) корневой сертификат для проверки HTTPS |

Остальные параметры (пины, тайминги) можно оставить по умолчанию.

> **Адрес сервера.** Если сервер запущен в Docker на вашем ПК, в `WEBHOOK_URL` нужен IP ПК в локальной сети (Windows: `ipconfig`, Linux/macOS: `ip a` / `ifconfig`), а не `localhost` — для ESP32 `localhost` указывает на неё саму.

> **HTTPS.** Для `https://` адресов без `WEBHOOK_CA_CERT` прошивка не проверяет сертификат сервера (`setInsecure`): трафик шифруется, но подмена сервера возможна. Для продакшена задайте CA.

## 3.2 Заливка

**Модуль PN532 к этому моменту подключать не обязательно.** Удобнее залить прошивку на «голую» ESP32 и проверить Wi-Fi, а модуль подключить потом ([04-hardware.md](04-hardware.md)) — так проще искать проблему, если что-то не заработает. Прошивка остаётся в памяти платы, после подключения модуля заново заливать ничего не нужно.

Если модуль **уже подключён** — тоже можно прошивать: пины D21/D22 не влияют на загрузку платы. Только перед тем как вставить USB, проверьте DIP-переключатели (1 = ON, 2 = OFF) и что VCC модуля идёт на **3V3**, а не на VIN.

1. **Файл → Открыть** → `firmware/nfc_reader/nfc_reader.ino` (вкладка `config.h` подтянется автоматически).
2. Проверьте плату (**DOIT ESP32 DEVKIT V1**) и порт (см. [01-environment-setup.md](01-environment-setup.md)).
3. Нажмите **✓ Проверить** — сборка без заливки. Первая идёт 1–3 минуты. Успех — строка «Скетч использует … байт (≈80%) памяти устройства»; 80% — нормально, это библиотека HTTPS.
4. Нажмите **→ Загрузка**. Плата сама перейдёт в режим прошивки (на DevKit V1 есть автосброс через USB), побегут проценты `Writing at 0x... (NN %)`.
5. После `Hard resetting via RTS pin...` плата перезагрузится сама — прошивка залита.

> **Кнопка BOOT** нужна, только если загрузка зависла на `Connecting........_____` и через ~10 секунд падает с ошибкой. Тогда нажмите «Загрузка» ещё раз и, как только появится `Connecting...`, зажмите **BOOT** на 1–2 секунды.

Через arduino-cli (из корня монорепы `esp32_projects`):
```powershell
arduino-cli compile --fqbn esp32:esp32:esp32doit-devkit-v1 projects/my_nfc/firmware/nfc_reader
arduino-cli upload  --fqbn esp32:esp32:esp32doit-devkit-v1 -p COM5 projects/my_nfc/firmware/nfc_reader
arduino-cli monitor -p COM5 -c baudrate=115200
```

## 3.3 Как работает прошивка

1. `setup()` — подключение к Wi-Fi (до 20 с), инициализация PN532 (5 попыток, затем перезагрузка), 2 вспышки LED.
2. `loop()`:
   - проверяет Wi-Fi и неблокирующе переподключается раз в 10 с;
   - ждёт карту до 500 мс (`NFC_READ_TIMEOUT_MS`), чтобы цикл не зависал;
   - **антидребезг:** пока та же карта лежит на считывателе, повторно она не отправляется (в логе один раз появится `... still on reader`). Снова отправится, если её убрать хотя бы на `SAME_CARD_COOLDOWN_MS` (1 с). Другая карта отправляется сразу;
   - отправляет POST на вебхук и мигает LED по результату.

### Отличия от исходного кода из инструкции

- Wi-Fi, URL и ключ вынесены в `config.h` (не попадают в git).
- Добавлены таймаут чтения, переподключение Wi-Fi, защита от повторной отправки, поддержка HTTPS, заголовок `X-API-Key`, индикация.
- Вместо зависания `while (1);` при отсутствии PN532 — повторные попытки и перезагрузка.

## 3.4 Формат запроса

```http
POST /webhook/nfc HTTP/1.1
Content-Type: application/json
X-API-Key: change-me

{
  "uid": "04A1B2C3D4E580",
  "uid_length": 7,
  "card_type": "NTAG215",
  "atqa": "0044",
  "sak": "00",
  "device_id": "nfc-reader-01",
  "firmware": "1.1.0",
  "rssi": -58,
  "uptime_ms": 123456
}
```

| Поле | Описание |
|---|---|
| `uid` | UID карты, hex в верхнем регистре (4 байта — Mifare Classic, 7 байт — NTAG/Ultralight) |
| `uid_length` | длина UID в байтах |
| `card_type` | тип карты (см. ниже) |
| `atqa` | ATQA (SENS_RES) — 2 байта, hex |
| `sak` | SAK (SEL_RES) — 1 байт, hex |
| `device_id` | из `config.h` |
| `firmware` | версия прошивки |
| `rssi` | уровень Wi-Fi сигнала, dBm |
| `uptime_ms` | время с момента включения |

### Как определяется тип карты

При обнаружении карта сообщает считывателю два служебных поля — **ATQA** и **SAK**. PN532 возвращает их вместе с UID, прошивка берёт их из ответа модуля и по SAK определяет семейство:

| SAK | ATQA | `card_type` |
|---|---|---|
| `08` | `0004` | MIFARE Classic 1K — самые частые белые карты и брелоки |
| `18` | `0002` | MIFARE Classic 4K |
| `09` | `0004` | MIFARE Mini |
| `10` / `11` | — | MIFARE Plus 2K / 4K |
| `00` | `0044` | MIFARE Ultralight / NTAG — модель уточняется, см. ниже |
| `20` | `0344` | MIFARE DESFire |
| `20` | другое | ISO 14443-4 smart card (банковские, транспортные, пропуска на JavaCard) |
| `28` / `38` | — | SmartMX с эмуляцией MIFARE Classic 1K / 4K |
| `88` | — | MIFARE Classic 1K (Infineon) |
| прочие | — | Unknown ISO 14443A |

Для **Ultralight/NTAG** (SAK `00`) прошивка дополнительно читает страницу 3 — Capability Container, где записан объём памяти: `NTAG213` (144 байта), `NTAG215` (504), `NTAG216` (888), `MIFARE Ultralight` (48). Если карта не размечена под NDEF, остаётся общее «MIFARE Ultralight / NTAG».

> Тип по SAK — это то, что карта **заявляет** о себе. Китайские «перезаписываемые» клоны (Magic/CUID) отвечают как MIFARE Classic 1K.

Время скана не передаётся — у ESP32 нет часов реального времени, сервер ставит метку времени при получении.

Если вебхук принимает не наш сервер, а n8n/Laravel — им достаточно разобрать этот JSON. Если ключ не нужен, оставьте `WEBHOOK_API_KEY ""`.

## 3.5 Монитор порта

**Инструменты → Монитор порта**, скорость **115200**.

Если модуль ещё **не подключён**, нормальный лог такой — Wi-Fi работает, модуль ожидаемо не найден, после 5 попыток плата перезагрузится и начнёт заново:

```
[WiFi] Connected. IP: 192.168.1.57, RSSI: -55 dBm
[NFC] I2C pins: SDA=GPIO21, SCL=GPIO22
[NFC] PN532 not found (attempt 1/5). Check wiring and DIP switches (I2C: 1=ON, 2=OFF)
```

Главное здесь — строка `[WiFi] Connected`. Если она есть, отключайте USB и подключайте модуль.

С **подключённым** модулем:

```
=== NFC reader nfc-reader-01, firmware 1.1.0 ===
[WiFi] Connecting to "MyWiFi"......
[WiFi] Connected. IP: 192.168.1.57, RSSI: -55 dBm
[NFC] Found chip PN532, firmware 1.6
[NFC] Waiting for an ISO14443A card...
[NFC] Card detected. UID: 3A7F1C09 (4 bytes), MIFARE Classic 1K [ATQA 0004, SAK 08]
[HTTP] 200 {"status":"ok","scan_id":1,"uid":"3A7F1C09","known":false,"name":null}
```

## 3.6 Индикация

Встроенный синий светодиод (GPIO2):

| Сигнал | Значение |
|---|---|
| 2 вспышки при старте | устройство готово |
| горит постоянно | идёт отправка вебхука |
| 1 длинная вспышка | сервер ответил 2xx |
| 3 коротких | ошибка отправки / сервер ответил не 2xx |
| серии быстрых вспышек при старте | PN532 не найден |
