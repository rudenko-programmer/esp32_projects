# esp32_projects — правила монорепы

Монорепа ESP32-проектов. Полные соглашения: [docs/conventions.md](docs/conventions.md). Ниже — то, что важно соблюдать всегда.

## Пользователь и окружение

- Windows 11, PowerShell 7. Команды и инструкции — **только Windows / PowerShell**, без вариантов для Linux/macOS.
- Язык общения, документации и комментариев в коде — **русский**.
- Docker Desktop поверх WSL2 с `networkingMode=mirrored` (`%USERPROFILE%\.wslconfig`, не менять). Следствие: доступность Docker-порта из LAN **нельзя проверить с самого ПК** (запрос на собственный LAN-IP не доходит) — проверка только с телефона в той же Wi-Fi: `http://<LAN-IP>:<port>`.
- Изменения брандмауэра требуют прав администратора — давать пользователю команду, а не выполнять самому.
- Плата по умолчанию — **DOIT ESP32 DEVKIT V1** (`esp32:esp32:esp32doit-devkit-v1`), USB-UART CH9102.

## Структура

- `projects/<project>/` — самодостаточные проекты (`README.md`, `docs/` с `docs/components/` и `docs/diagrams/`, `firmware/<sketch>/`, опционально `server/`, `hardware/`).
- `docs/` — общие документы (настройка ESP32, соглашения, новый проект).
- `shared/` — общий код; заводить, только когда он реально нужен 2+ проектам.
- `templates/project/` + `tools/new-project.ps1` — создание нового проекта.
- `.claude/agents/` — агенты, имя с префиксом проекта (`my-nfc-webhook`); общие для всей монорепы — с префиксом `repo-` (`repo-diagrams`).
- Проект не ссылается на файлы соседнего проекта.

## Правила работы

- **Секреты:** реальные значения только в `firmware/**/config.h` и `server/.env` (оба в `.gitignore`). В репозиторий — `config.example.h` / `.env.example` с заглушками. Никогда не выводить ключи целиком без нужды.
- **Новый настраиваемый параметр** прошивки → в `config.example.h` + значение по умолчанию через `#ifndef` в скетче, чтобы старые `config.h` продолжали собираться. Параметр сервера → в `.env.example`.
- **Docker:** `docker-compose.yml` начинается с `name: <project>`; порт на хосте — из реестра портов в `docs/conventions.md` (добавлять туда новые). Никогда не выполнять `docker compose down -v`, `docker volume rm` и не удалять базы данных без явной просьбы.
- **Железо:** перед любыми перекоммутациями — USB отключить. В инструкциях по подключению это всегда отдельный шаг.
- **Компоненты:** каждая подключаемая деталь описывается в `projects/<project>/docs/components/<маркировка>.md` (образец — `templates/component.md`): кратко, маркировка с расшифровкой, контакты, какая комбинация что делает, напряжение и ток, проверка, документы. Даташиты — копией в `docs/components/datasheets/` + ссылка на источник. Значения не из официального даташита этой детали помечать как ориентир с указанием источника. Подробно — `docs/conventions.md`, раздел «Компоненты».
- **Схемы — кодом, не ASCII:** распиновки, принципиальные схемы и схемы подключения рисуются в `projects/<project>/docs/diagrams/schematics.ipynb` (schemdraw — схемы и детали, WireViz — подключения), сохраняются в SVG рядом и вставляются в документы `![...](diagrams/<имя>.svg)`. После правки — `./tools/diagrams.ps1 render`, затем посмотреть результат (SVG → PNG через `rsvg-convert` в том же образе). Подробно — `docs/diagrams.md`. Рисование и правку схем делегировать агенту **`repo-diagrams`**.
- **Python — только в Docker** (образ `esp32-diagrams`, `tools/diagrams.ps1`), на ПК через pip ничего не ставить. Если Docker не работает — виртуальное окружение внутри проекта, не глобально.
- **Перед любой установкой** (pip, winget, скачивание программ, сборка/скачивание Docker-образов) — сначала сказать пользователю, что и куда ставится, и дождаться согласия. Удаление — тоже по согласию.
- **Документация обновляется вместе с кодом:** изменил поведение, пины, параметры, API → поправь `docs/` проекта и README. Новые документы нумеруются по порядку сборки (`NN-тема.md`).
- **Git** (подробно — `docs/conventions.md`, раздел «Git»):
  - В `main` напрямую не коммитить и не пушить. Работа — в отдельной ветке от свежего `main`, в `main` попадает только через Pull Request на GitHub.
  - Ветка: `<область>/<кратко-что>` (`my_nfc/forward-retry`, `repo/ci`). Сообщение коммита: `<область>: <что сделано>` по-русски.
  - **Claude не указывать в авторах:** никаких `Co-Authored-By: Claude ...` в коммитах и `Generated with Claude Code` в описаниях PR.
  - Коммитить только по просьбе. Перед коммитом проверить, что `config.h` / `.env` не попали в индекс.
  - Remote: `origin` = https://github.com/rudenko-programmer/esp32_projects.git
